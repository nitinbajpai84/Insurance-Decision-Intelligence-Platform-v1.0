- **Latency (target < 4s; V1 baseline ~6.5s):**
  - Call 1: **total_latency_ms = 2,095** (wall 2,158 ms) ✅
  - Call 2: **total_latency_ms = 2,304** (wall 2,381 ms) ✅
  - Step breakdown (call 1): context 407ms · sql_gen 813ms · execution 45ms · insight 643ms

**🟡 Deviation (by design):** the pipeline does **not** emit discrete `sql_validated` and `result_validated` SSE *events*. Validation is folded into the `sql_generated` event (`validation_status`) and the final `complete` event metadata (`sql_validated=true`, `result_validated=true`). The 6-step tracker in the UI derives those two steps from that metadata. `insight_token` arrives as multiple events (3 chunks here).

## 9. Semantic Cache (repeat question) — 🟡 WARNING

Asked the identical question twice:

| Call | cache_hit | latency |
|---|---|---|
| 1 | false | 2,095 ms |
| 2 | false | 2,304 ms |

**Expected:** call 2 → `cache_hit = true`, latency < 500 ms.
**Actual:** call 2 was a full fresh run (no hit).

**Root cause:** the **read path is implemented** — the context agent embeds the question and searches `insurance_query_history` with a 0.92 cosine threshold, and the orchestrator has a cache-hit short-circuit that skips SQL + execution and streams the cached answer. **But there is no write-back**: a completed fresh run is never appended to `insurance_query_history` (LanceDB) or `semantic_cache` (DuckDB). As a result, only pre-seeded/embedded history can ever produce a hit; newly-asked questions never populate the cache, so an immediate repeat re-runs the full pipeline.

**Remediation (small, isolated):** after a successful run in `orchestrator.stream_pipeline`, embed the question and upsert `{question, role, answer_summary, sql_used, confidence, latency}` into `insurance_query_history` (and/or `semantic_cache`). Honor `CACHE_TTL_HOURS` on read. This closes the loop and makes check #9 pass.

**Severity:** WARNING, not blocker — the cache infrastructure (tables, read path, short-circuit, UI ⚡ badge + skip animation) is present and correct; only the write-back is missing, so the feature is incomplete rather than broken.
